# 改动总结 - 2026-01-10

## Order Latency Caching (订单延迟缓存)

### 问题背景

之前订单延迟计算只在首次确认时有效，后续状态变化（如 Filled、Canceled）会显示 0ms 延迟。用户反馈："一个订单我们只用关心一个延迟"。

### 解决方案

在订单首次收到交易所确认时计算并缓存延迟，所有后续状态变化复用该缓存值。

### 核心修改

#### 1. `order-recorder/src/convert.rs`

- 新增 `calculate_first_ack_latency()` 函数：
  ```rust
  pub fn calculate_first_ack_latency(prev_order: &Order, new_order: &Order) -> Option<i64> {
      // 检测首次确认: prev_order.exch_timestamp == 0 AND new_order.exch_timestamp > 0
      if prev_order.exch_timestamp == 0
          && new_order.exch_timestamp > 0
          && new_order.local_timestamp > 0
      {
          let latency = new_order.exch_timestamp - new_order.local_timestamp;
          if latency > 0 && latency < MAX_REASONABLE_LATENCY_NS {
              return Some(latency);
          }
      }
      None
  }
  ```

- 修改 `create_order_update()` 接受 `cached_latency: Option<i64>` 参数

#### 2. `order-recorder/src/hook.rs`

- 新增 `latency_cache: RwLock<HashMap<u64, i64>>` 字段到 `OrderHookContext`
- 在 `handle_order()` 中实现缓存逻辑：
  ```rust
  let cached_latency = {
      let cache = self.latency_cache.read().unwrap();
      if let Some(&latency) = cache.get(&order_id) {
          Some(latency)  // 使用缓存的延迟
      } else {
          // 计算首次确认延迟并缓存
          if let Some(latency) = calculate_first_ack_latency(prev_order, new_order) {
              let mut cache = self.latency_cache.write().unwrap();
              cache.insert(order_id, latency);
              Some(latency)
          } else {
              None
          }
      }
  };
  ```
- 新增清理逻辑：订单终态时移除缓存条目防止内存泄漏

### 效果

| 订单状态 | 修改前延迟 | 修改后延迟 |
|----------|------------|------------|
| New      | 50ms       | 50ms       |
| PartiallyFilled | 0ms | 50ms       |
| Filled   | 0ms        | 50ms       |
| Canceled | 0ms        | 50ms       |

## Docker Binary Hot-Reload (Docker 二进制热更新)

### 问题背景

之前更新策略或服务二进制需要重新构建 Docker 镜像，耗时且不便于开发迭代。

### 解决方案

使用 bind mount 将宿主机编译的二进制直接挂载到容器中。

### 修改文件

#### `deploy/docker/docker-compose.yml`

新增二进制 bind mounts：
```yaml
volumes:
  # Binary files (bind mount for hot-reload without image rebuild)
  - ../../target/release/obi_mm_live:/usr/local/bin/obi_mm_live:ro
  - ../../target/release/order-recorder:/usr/local/bin/order-recorder:ro
  - ../../target/release/connector:/usr/local/bin/connector:ro
  - ../../target/release/collector:/usr/local/bin/collector:ro
  - ../../target/release/hft-supervisor:/usr/local/bin/hft-supervisor:ro
  - ../../target/release/hft-server:/usr/local/bin/hft-server:ro
  - ../../target/release/hftctl:/usr/local/bin/hftctl:ro
```

### 使用流程

```bash
# 1. 在宿主机编译
cargo build --release -p order-recorder

# 2. 重启容器使用新二进制
docker compose restart hft
```
