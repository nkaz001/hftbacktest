# 改动总结 - 2026-01-09

## Multi-Connector Support (多连接器支持)

### 概述

实现了 HFT Supervisor 的多连接器支持，允许同时运行多个交易所连接器（如 Binance Futures + Bybit），每个 Bot 可以指定使用哪个连接器。

### 核心设计

- 使用 `HashMap<InfraComponent, ManagedComponent>` 替代固定数组
- `InfraComponent::Connector(String)` 通过名称标识连接器
- 向后兼容：同时支持 `[connector]` (旧格式) 和 `[[connectors]]` (新格式)
- Collector 使用第一个连接器的 IPC

### Supervisor 代码修改

#### 1. `supervisor/src/config.rs`

- 新增 `connectors: Vec<ConnectorConfig>` 字段
- 新增 `connector: Option<String>` 到 BotConfig
- 新增辅助方法：
  - `all_connectors()` - 返回所有连接器配置
  - `get_connector(name)` - 按名称获取连接器
  - `default_connector_name()` - 返回默认连接器名称
- 更新验证逻辑支持多连接器

#### 2. `supervisor/src/infra.rs`

- `InfraComponent::Connector` 改为 `InfraComponent::Connector(String)`
- `components` 从固定数组改为 `HashMap<InfraComponent, ManagedComponent>`
- 更新方法：
  - `start_component()` - 处理命名连接器
  - `stop_component()` - 处理命名连接器
  - `start_auto_start()` - 启动所有连接器
  - `stop_all()` - 停止所有连接器
  - `monitor()` - HashMap 迭代
  - `handle_pending_restarts()` - HashMap 访问
  - `spawn_component()` - 按名称获取连接器配置
- 更新 `ClusterHealth` 结构支持多连接器

#### 3. `supervisor/src/ipc.rs`

- 新增 `ConnectorStatus` 结构：
  ```rust
  pub struct ConnectorStatus {
      pub name: String,
      pub status: String,
      pub healthy: bool,
  }
  ```
- `StatusResponse.connector` 改为 `connectors: Vec<ConnectorStatus>`

#### 4. `supervisor/src/hftctl.rs`

- 更新状态显示，支持多连接器：
  ```
  connector:bf     running (healthy)
  connector:bybit  running (healthy)
  ```

#### 5. `supervisor/src/manager.rs`

- Bot 启动时传递 `--connector` 参数：
  ```rust
  if let Some(connector) = connector_name {
      cmd.arg("--connector").arg(&connector);
  }
  ```

### 配置文件修改

#### 1. `deploy/docker/config/cluster.toml`

从 `[connector]` 改为 `[[connectors]]` 数组：

```toml
# Binance Futures Testnet
[[connectors]]
name = "bf"
type = "binancefutures"
config_file = "/etc/hft/binancefutures.toml"
auto_start = true

# Bybit Demo Trading
[[connectors]]
name = "bybit"
type = "bybit_rest"
config_file = "/etc/hft/bybit.toml"
auto_start = true
```

```toml

connector = "bf"

[[bots]]
id = "obi_mm_btcusdt_bybit"
symbol = "BTCUSDT"      # Bybit: 大写
connector = "bybit"
```

### Symbol 大小写规则

不同交易所有不同的 symbol 格式要求：
- **Binance**: 小写 (`btcusdt`, `ethusdt`, `solusdt`)
- **Bybit**: 大写 (`BTCUSDT`, `ETHUSDT`, `SOLUSDT`)

## reduceOnly Support (reduceOnly 支持)

### 概述

为所有连接器添加 `reduceOnly` 参数支持，允许止损订单绕过交易所的最小名义值要求（如 Binance Futures 的 $100 限制）。

### 问题背景

止损订单在 Binance Futures Testnet 上失败：
```
Order submission failed: OrderError { code: -4164, msg: "Order's notional must be no smaller than 100 (unless you choose reduce only)." }
```
原因：订单价值 `90450 × 0.001 = $90.45` < $100 最小名义值

### 核心修改

#### 1. `hftbacktest/src/types.rs`

- `Order` 结构体添加 `reduce_only: bool` 字段
- `OrderRequest` 结构体添加 `reduce_only: bool` 字段
- `Bot` trait 的 `submit_buy_order` 和 `submit_sell_order` 方法添加 `reduce_only` 参数

#### 2. `hftbacktest/src/live/bot.rs`

- `LiveBot` 实现更新，传递 `reduce_only` 到订单

#### 3. `hftbacktest/src/backtest/mod.rs`

- 回测 Bot 实现添加 `_reduce_only` 参数（占位符，回测中忽略）

#### 4. 连接器修改

| 连接器 | 文件 | 修改 |
|--------|------|------|
| Binance Futures | `connector/src/binancefutures/rest.rs` | `&reduceOnly=true` 添加到 REST body |
| Binance Futures | `connector/src/binancefutures/mod.rs` | 传递 `order.reduce_only` |
| Binance PAPI | `connector/src/binancepapi/rest.rs` | `&reduceOnly=true` 添加到 REST body |
| Binance PAPI | `connector/src/binancepapi/mod.rs` | 传递 `order.reduce_only` |
| Bybit | `connector/src/bybit/msg.rs` | `"reduceOnly": true` 添加到 JSON |
| Bybit | `connector/src/bybit/ordermanager.rs` | 填充 `reduce_only` 字段 |

#### 5. 策略修改

| 文件 | 修改 |
|------|------|
| `strategies/obi_mm_rust/src/strategy.rs` | 止损订单使用 `reduce_only=true`，网格订单使用 `false` |
| `strategies/template_strategy/src/main.rs` | 添加 `reduce_only=false` 参数 |

#### 6. Python 绑定 (FFI 层)

| 文件 | 修改 |
|------|------|
| `py-hftbacktest/src/backtest.rs` | FFI 函数默认传递 `false` |
| `py-hftbacktest/src/live.rs` | FFI 函数默认传递 `false` |

### 向后兼容性

- **Python API**: 保持不变，FFI 层默认 `reduce_only=false`
- **回测**: 参数被忽略（交易所特有功能）
- **现有代码**: 所有调用点已更新
